## 2. Mechanism deep dives

### 2.1 Tracker script (client side)

ESTABLISHED (`U:tracker/index.ts`):
- Config precedence: `data-*` attribute on the script tag, else `window.umamiConfig[camelCase]` (`:285-292`). Keys (`:302-315`): `website-id`, `host-url`, `distinct-id`, `tag`, `salt`, `salt-rotation` (hourly/daily/weekly/monthly -> UTC prefix of ISO time, `:351-359`), `auto-track` (default on), `do-not-track`, `exclude-search`, `exclude-hash`, `domains` (comma list; hostname must match or sends are skipped client-side, `:456-462`), `fetch-credentials` (default `omit`), `performance`, `auto-pageview`; plus `errors`, `release`, `environment` (`:746-754`) and `before-send` (name of a global function, `:294-300`).
- Pageview payload (`:206-217`): `website, screen (WxH), language, title, hostname, url (normalized), referrer (same-origin referrers have origin stripped, `:347-349`), tag, id (distinct id), salt`. `normalize()` removes `search`/`hash` when configured (`:333-345`).
- SPA: wraps `history.pushState/replaceState`; on URL change sets `currentRef=currentUrl`, and fires `track` after 300 ms if the URL differs and `auto-pageview` is on (`:380-411`). Popstate/hashchange are not hooked (INFERRED: back/forward without pushState is not tracked).
- Click events: capture-phase document listener; walks `closest('[data-umami-event]')`; collects `data-umami-event-*` attrs into `data` (`:413-452`). For `<a>` same-tab clicks it `preventDefault`s, sends, then navigates in `.finally` (so a slow collect delays navigation).
- JS API: `umami.track()` / `track(name)` / `track(name, data)` / `track(obj)` / `track(fn)` (`:507-515`), `umami.identify(id|obj, data)` (`:517-535`), `umami.getSession()`, `umami.captureException`. `data-distinct-id` triggers identify at load (`:768-770`).
- Kill switches (`:456-462`): `localStorage['umami.disabled']`, `window.name === 'umami.disabled'` in iframes, `domains` mismatch, `data-do-not-track="true"` + browser DNT, server reply `{disabled:true}` (`:490-492`).
- Transport: `fetch(endpoint, {keepalive:true, method:POST, credentials:'omit'})` with headers `x-umami-website-id`, `x-umami-hostname`, and `x-umami-cache` (the session token returned by the previous call) (`:476-485`). **No cookies and no localStorage ids**: continuity is the cache token held in JS memory only, so a full page load without a token re-derives the session from IP/UA (see 2.2).
- Performance: Web Vitals collection via PerformanceObserver; flush on pagehide/visibilitychange/10 s timeout or SPA navigation (`:538-760`); sent as `type:'performance'`.

OVELIO gap: snippet = bare tag (`O:analytics.tsx:515`). To reach parity add an "advanced options" generator for the attrs above, a copy-ready SPA/consent snippet and a test-send button. Caveat: `salt`/`salt-rotation` attrs are ignored by the server unless env `ENABLE_CLIENT_SALT` is set (`U:lib/collection-session.ts:107-109`) which OVELIO does not set (`O:compose.yaml:335-343`).

### 2.2 Collect endpoint, session and visit derivation (how a hit becomes rows)

ESTABLISHED, `U:app/api/send/route.ts` unless noted:
1. No auth (`parseRequest(..., {skipAuth:true})`, `:25`). Body schema (`U:app/api/send/request-schema.ts:84-136`): `type` in `event|identify|performance|error`; exactly one of `website|link|pixel` UUID; `data` must be an object, depth <= 32, numbers < 1e15; `name` and `tag` may not start with `= + - @ TAB CR` (CSV-injection guard); `salt` <= 100 chars; `timestamp` unix seconds <= 2147483647; revenue >= 1e14 rejected.
2. Website existence check unless a valid cache token exists (`:63-85`). **No hostname/domain enforcement** (website `domain` is cosmetic).
3. Client info (`U:lib/detect.ts:136-148`): IP from `payload.ip` else headers (`CLIENT_IP_HEADER` first, then `true-client-ip, cf-connecting-ip, ..., x-forwarded-for`, `U:lib/ip.ts:3-17,180`), UA from `payload.userAgent` else header; geo from CDN headers (Cloudflare/Vercel/CloudFront/EdgeOne, `U:lib/detect.ts:12-47`) else MaxMind `GeoLite2-City.mmdb` (`:113-133`); `browser/os/device` from payload override or `detect-browser`/UAParser; `device` = `laptop` when desktop and screen width <= 1920 (`:49-61`).
4. Bot gate: `isbot(userAgent)` unless `DISABLE_BOT_CHECK` -> returns `{beep:'boop'}` 200 (`:97-99`). IP block via `IGNORE_IP` incl. CIDR (`:102-104`, `U:lib/detect.ts:150-179`).
5. **Session id** (`U:lib/collection-session.ts:86-120`, `U:lib/crypto.ts:56-62,73-102`): `sessionId = uuidv5( sha512(sourceId + ip + userAgent + sessionSalt + (distinctId||'') + appSecret) )`. `sessionSalt` = hash of start-of-period; **default period is monthly** (`SALT_ROTATION` unset, `crypto.ts:88-93`), optional day/week/month or fixed string. Raw IP is hashed in, never stored (session table has no ip column, `U-prisma:55-85`). Consequence (INFERRED): a "visitor" = same IP+UA within a month; roaming users/IP changes split; shared NAT+identical UA merges; across month boundary the same person gets a new id.
6. **Visit id**: `visitId = cache.visitId || uuidv5(sessionId, hash(startOfHour(createdAt)))`; a new one is minted when session drift occurs or `now - iat > 1800` s (`collection-session.ts:110-118`). The token's `iat` is carried forward unchanged (`route.ts:320-325`; test asserts it is preserved, `U:app/api/send/route.test.ts:650,675`), so INFERRED the 30 min is a fixed window from visit start, not sliding inactivity (tests are nonetheless titled "30 minutes of inactivity", `route.test.ts:678`). Backfilled hits (`timestamp` given) never expire the visit (`:115`, test `route.test.ts:~829`). Without a token (server-side sends, blocked JS memory) the visit is the hour bucket.
7. Cache token = JWT `{websiteId, sessionId, visitId, iat, sessionLinkId, type:'cache'}` signed with the app secret, returned in the response body and echoed by the client in `x-umami-cache` (`route.ts:320-325,67-75`). No expiry claim.
8. Postgres mode creates a `session` row when no token or session drift (`route.ts:122-140`); ClickHouse mode derives sessions from events (`updateSession.ts:42-49` comment). Session attributes are therefore **frozen at first hit**.
9. Event branch (`route.ts:142-253`): path = `pathname + hash` (hash is part of `url_path` unless `exclude-hash`, `:146-147`), query separate (`url_query`); `REMOVE_TRAILING_SLASH` env optional; referrer split into path/query/domain, `www.` stripped, **self-referrals null their domain** (`:175-197`); UTM x5 and click ids (`gclid, fbclid, msclkid, ttclid, li_fat_id, twclid`) read from the *landing URL query* (`:155-168`); `event_type` = 3 link, 4 pixel, 2 custom (has `name`), else 1 pageview (`:199-205`, `U:lib/constants.ts:125-131`); then `saveEvent`.
10. `saveEvent` (`U:queries/sql/events/saveEvent.ts:73-175`): truncations from `FIELD_LENGTH` (event name 50, tag 50, hostname 100, url/title 500, distinctId 50; `constants.ts:278-297`). If `data` present -> flatten to `event_data` rows (`lib/data.ts:11-25`: dotted keys, string/number/boolean/date/array types, arrays stored as JSON string, dropped to NULL if > 500 chars `:56-64`; the "50 properties" comment in `U:tracker/index.ts:81-86` is not enforced in code I read). If `data.revenue` (number|string > 0) **and** non-empty `data.currency` -> a `revenue` row (`saveEvent.ts:154-173`). Event data and revenue are written *after* the event row, non-transactionally (INFERRED partial-write risk).
11. identify branch (`route.ts:254-290`): requires a `website` + `id`; computes `hash(sessionId, distinctId)`; writes `session_link` (idempotent insert) and sets `session.distinct_id` only if empty (`updateSession.ts:22-39`); then upserts `session_data` from `data` (`@@unique([sessionId,dataKey])`, `U-prisma:223`). Because `distinctId` is in the session-id hash, identifying changes the computed id: `resolveIdentifiedSession` (`collection-session.ts:30-84`) keeps the anonymous session if the IP/UA fingerprint is unchanged and `tryClaimAnonymousSession` wins an advisory-lock check that no *other* identity already owns it (`U:queries/sql/sessions/tryClaimAnonymousSession.ts:30-94`; ClickHouse needs Redis `SET NX`, else declines, `:110-112`). One session can be linked to many ids; `getLinkedSessionIds` / `getLinkedDistinctIds` read the link table (`U:queries/sql/sessions/getLinkedSessionIds.ts`).
12. Pixels/links reuse `/api/send` internally with `pixel`/`link` id as the "website" (`U:app/(collect)/{p,q}/[slug]/route.ts`); the `session`/`website_event` rows carry that id as `website_id`.
13. Batch: `POST /api/batch` max 500 items, serial, shares one cache token (`U:app/api/batch/route.ts:7-60`).
14. CORS: `/api/*` is `Access-Control-Allow-Origin: *` with all headers allowed (`U:next.config.ts:64-86`). OVELIO exposes only `/script.js` and `/api/send` publicly (`O:Caddyfile:21-45`); keep it that way (the whole Umami admin API would otherwise be CORS-open).

Data model (ESTABLISHED):
- Postgres (`U-prisma`): `session` (attrs frozen), `session_link`, `website_event` (one wide table, `event_type` int, UTM, click ids, CWV columns, 14 composite indexes `:169-182`; note **no `distinct_id` column** in Postgres events, identity lives on `session`), `event_data`, `session_data`, `revenue`, `segment` (type segment|cohort, JSON params), `report` (saved reports, JSON), `link`, `pixel`, `board`, `share`, `annotation`, `session_replay`, `heatmap_event`, `error_*`.
- ClickHouse (`U-ch:1-258`): `website_event` (has `distinct_id`, ordered by hour/website/session/visit), `event_data`, `session_data` (ReplacingMergeTree + projection), `website_event_stats_hourly` AggregatingMergeTree + MV that pre-aggregates per visit/hour (entry/exit via argMin/argMax states). OVELIO runs Postgres only (`O:compose.yaml:322-336`).

### 2.3 Filters and request parsing

- `FILTER_COLUMNS` (23): path, entry, exit (all `url_path`), referrer/domain (`referrer_domain`), hostname, distinctId, title, query, os, browser, device, country, region, city, language, event, tag, eventType, utmSource/Medium/Campaign/Content/Term (`U:lib/constants.ts:83-108`). `SESSION_COLUMNS` (join `session`): browser, os, device, screen, language, country, city, region, distinctId (`:66-76`). `screen` and `channel` are *metrics* types but not filters.
- Operators (`:153-170`): `eq, neq, s (set), ns (not set), c, dnc, re, nre, t, f, gt, lt, gte, lte, bf, af`. On dimension filters the Postgres implementation handles only `eq/neq/c/dnc/re/nre` (`U:lib/prisma.ts:146-179`); `s/ns/t/f/gt/lt/gte/lte/bf/af` are meaningful only for typed property filters (`:349-445`). Wire syntax: `?path=c./pricing` = operator prefix + dot; comma list for eq/neq (`U:lib/params.ts:29-52`); suffix digits allow repeats (`browser1`, `os2`, `U:lib/request.ts:41-52`).
- Property filters: `pf_<name>=<type>.<op>.<value>` (event data), `epf<n>`, `spf<n>` (session data), exists-subqueries (`prisma.ts:349-445`).
- Logic: AND by default; `match=any` ORs everything except `eventType` (`prisma.ts:181-226`). `referrer` filter auto-excludes self-referrals (`:205-209`).
- Segments: stored `{filters[], sessionPropertyFilters[], match, dateRange?, action?}` (`U:lib/schema.ts:407-426`). A `segment=<id>` param merges its filters into the request (`U:lib/request.ts:163-175`). A `cohort=<id>` adds a join to "sessions that did `action` (path|event) within `dateRange` and match filters" (`request.ts:177-205`, `prisma.ts:228-247`).
- `excludeBounce` join drops visits with a single pageview and no custom event (`prisma.ts:249-267`).
- Date range: either `startAt/endAt` or `period` (`today,24h,7d,30d,0day,24hour,0week,7day,0month,30day,90day,0year,6month,12month`, `U:lib/date.ts:56-71`), `unit`, `timezone`, `compare=prev|yoy` (`U:lib/schema.ts:58-99`). Website `resetAt` floors the start date (`U:lib/request.ts:~106-120`).

OVELIO state: equality only, 18 keys (`O:index.ts:695-699`); `queryFilters` forwards raw user text (`:863-877`), so a user typing e.g. `c.foo` or `re.^/blog` into a filter box would be parsed by Umami as an operator (INFERRED, undocumented behaviour; and a legitimate value that starts with an operator token would be misread). ### 2.4 Traffic-source classification (channels)

ESTABLISHED, `U:queries/sql/getChannelMetrics.ts`:
- Input per hit (excluding custom events and performance, `event_type NOT IN (2,5)`, `:53`): `referrer_domain, url_query, utm_medium, utm_source, hostname`.
- First matching WHEN wins (`:57-71`):
  1. `direct` if referrer empty AND url_query empty.
  2. `paidAds` if `url_query` contains any `PAID_AD_PARAMS` (`ad_id=, aid=, dclid=, epik=, gclid=, li_fat_id=, msclkid=, ob_click_id=, pc_id=, rdt_cid=, scid=, ttclid=, twclid=, utm_medium=cpc|paid|paid_social, utm_source=google`, `U:lib/constants.ts:~402-420`). **`fbclid` is not in the list** although it is stored as a click id.
  3. `referral` if utm_medium ~ referral|app|link; `affiliate` if utm_medium ~ affiliate; `sms` if utm_medium or utm_source ~ sms.
  4. `llm` if referrer in {chatgpt.com, claude.ai, copilot.microsoft.com, gemini.google.com, meta.ai, perplexity.ai}.
  5. `<prefix>Search` if referrer in search list (google., bing.com, duckduckgo.com, ecosia.org, baidu.com, yandex., msn.com, search.brave.com) or utm_medium ~ organic; `<prefix>Social` for social list (facebook, instagram, linkedin., reddit., t.co, twitter.com, x.com, tiktok., pinterest., snapchat., threads.net, bsky.app, news.ycombinator.com ...); `email` if referrer in webmail list (gmail., hotmail., mail.yahoo., outlook., proton.me, protonmail.) or utm_medium contains `mail`; `<prefix>Shopping`, `<prefix>Video` (youtube., twitch.).

### 2.5 Events, goals, funnels, journeys, retention, attribution, revenue (query algorithms)

- **Stats** (`U:queries/sql/getWebsiteStats.ts:43-74`): group by (session, visit); `pageviews` = hits with `event_type NOT IN (2,5)`; `visitors` = distinct session ids; `visits` = distinct visit ids; **bounce** = visit with exactly one pageview and no custom event; `totaltime` = sum(max-min of pageview timestamps) per visit => a one-page visit contributes 0 seconds. `comparison` computed by re-running over the previous period/yoy (`U:app/api/websites/[websiteId]/stats/route.ts:30-39`).
- **Goals** (`getGoal.ts:56-77`): `count(distinct session_id)` doing path|event (wildcard `*` via `getWildcardMatch`, `U:lib/search.ts`) / `count(distinct session_id)` of all sessions in range under same filters. Session-level, no value.
- **Funnel** (`getFunnel.ts:96-160`): CTE chain `level1..levelN`. Level 1 = distinct (session, time) matching step 1 in range; level k = events of the **same session** with `created_at BETWEEN prev.created_at AND prev.created_at + window minutes` matching step k and inside the range; result = `count(distinct session_id)` per level (`:158`). Notes (INFERRED from SQL): inclusive lower bound lets step k match the same instant as step k-1; **session-scoped, so session-salt rotation or IP change breaks continuity**; steps match by `url_path` or `event_name` with `*` wildcards; event steps accept property filters (`eq/neq/c/dnc` on `event_data`, `:58-94`); path steps ignore filters (`:116-124`). Returns visitors/previous/dropped/dropoff/remaining (`FunnelResult`, `:26-32`); OVELIO only maps `value`+`visitors` (`O:index.ts:99`).
- **Journey** (`getJourney.ts:110-132`): events keyed by `visit_id` ordered by time, label = `event_name` else `url_path`, pivot to columns e1..eN (2-7), group-by sequence, top 100; `startStep`/`endStep` filters.
- **Retention** (`getRetention.ts:48-98`): cohort date = first day (tz-aware) a session appears in range; activity = distinct (session, day offset); output rows `(cohort date, day offset <= 31, cohort size, returned, %)`. Because session ids rotate monthly (2.2), **retention beyond the salt period is structurally undercounted** (INFERRED) unless `SALT_ROTATION` is a fixed string or users are identified (and even then retention keys on `session_id`, not `distinct_id`).
- **Attribution** (`getAttribution.ts:51-156`): `events` = sessions that hit the target step (path or event) in range; model `first-click` = the session's earliest hit in range, `last-click` = latest hit strictly before the (last) conversion; then for that attributing hit report distinct sessions by referrer (excl. self), paid-ads bucket (first matching click id: gclid>fbclid>msclkid>ttclid>li_fat_id>twclid), and each UTM column (top 20); `total` = pageviews/visitors/visits of the conversion. Join key is `created_at` equality with the session (fragile when two hits share a timestamp, INFERRED). **Session-scoped touch history only, no cross-session lookback, no revenue.**
- **Revenue** (`getRevenueStats.ts:41-77`): sum revenue rows (currency match, no FX) joined to sessions passing the filters; metrics split by country/region/referrer/channel (`U:queries/sql/revenue/getRevenueMetrics.ts`); chart by unit; ARPU = sum / sessions. `importedRevenue.ts` exists for imported rows (not analysed).
- **UTM report** (`getUTM.ts:38-53`): pageviews grouped by one UTM column, top 50.
- **Breakdown** (`getBreakdown.ts`): group by up to N dims of {path, referrer, title, query, os, browser, device, country, region, city, tag, hostname, distinctId, language, event, utm*}.
- **Sessions/realtime**: sessions listing joins `session`+events with `search` over distinct_id/city/browser/os/device (`U:queries/sql/sessions/getWebsiteSessions.ts:30-37`); realtime = last 30 min activity + series; active = distinct sessions in last 5 min (`getActiveVisitors.ts:20`).
- **Performance**: p50/p75/p95 style stats per metric with thresholds `WEB_VITALS_THRESHOLDS` (`U:lib/constants.ts:117-123`).

### 2.8 Defects and risks found in the OVELIO wrapper (all ESTABLISHED unless marked)

1. 3. Tracked-link, pixel and share URLs shown in the UI are not routed to Umami by Caddy (`O:Caddyfile:100-105`; `O:analytics.tsx:598,2790,2934,3006`) (INFERRED 404; correct if `TRACKING_ORIGIN` is deployed as a separate host that proxies to Umami - UNVERIFIED, no compose entry sets it).
4. Adapter drops `channel`/`screen` filters that the console route accepts (`O:route.ts:93-96` vs `O:index.ts:695-699`).
5. Route/adapter limit drift: step value 200 vs 500 chars (`O:route.ts:53` vs `O:index.ts:98`); ad-hoc funnel window <=1440 vs saved <=10080; breakdown fields 4 vs 10; attribution step 300 vs 500.
6. `timezone=UTC` forced (`O:index.ts:856`): "today", day buckets and retention cohorts are UTC days for every tenant.
7. Attribution endpoint ignores report filters and the `currency` parameter (`O:route.ts:886-890`, `O:index.ts:1343-1356`).
8. Single shared Umami admin login for all OVELIO users (`O:index.ts:1021-1048`), so Umami-side ACL/audit is meaningless; OVELIO roles are the only guard (`O:route.ts:36,105-106`).
9. `/share/` and Umami's `/api/*` CORS `*` (`U:next.config.ts:64-86`) are safe only because Caddy exposes nothing else; any future "forward /api" rule is a data leak.

## 3. Better-than opportunities (grounded in the weaknesses above)

1. **Consent-aware identity stitching (email click -> web session -> contact)**. Umami has the primitives (`distinct_id`, `session_link` many-to-many, atomic claim, `session_data`) but nothing that feeds them; OVELIO currently forbids it (`O:README.md:112`, `O:analytics.tsx:3172`). Design:
   - Campaign link carries an opaque, signed, expiring token (`ovl=<HMAC(contactId|campaignId|exp)>`), appended by OVELIO's link rewriter (Listmonk/Mautic link redirect hop; Caddy already forwards `/link/...` and `/r/...`, `O:Caddyfile:49,62`).
   - A small OVELIO tracker wrapper (loads Umami `script.js` with `data-auto-track=false`) waits for consent (CMP callback or a first-party consent cookie), then calls `umami.identify(<pseudonymous id>, {campaign, contact_segment})`. Use an HMAC pseudonym (<= 50 chars, `FIELD_LENGTH.distinctId`, `U:lib/constants.ts:290`) so Umami never stores the email.
   - OVELIO keeps the join table `visitor_pseudonym <-> contact_id` with consent state and TTL; deletion/DSAR = delete mapping (web events become anonymous again). Honour `dnt`, `umami.disabled`.
   - Without consent: still attribute at campaign level via UTM (current behaviour) - strictly better than Umami, which cannot do either.
   - Fix the stitching blind spots first: Umami's session id includes the monthly salt and IP/UA (2.2), so stitch on `distinct_id`/`session_link`, not on `session_id`; reports (retention, funnels) must be re-keyed on distinct id for identified users.
2. **Campaign-to-revenue attribution**: Umami's attribution has no revenue weighting and no lookback (2.5). Join `revenue` rows (per event with `currency`) to the attributing touch and to the OVELIO campaign id carried in `utm_campaign`/`utm_content`; add multi-touch (linear, time-decay, position-based) over a configurable lookback across sessions via identity. Add FX normalisation and order-id idempotency (Umami has none, INFERRED).
3. **Behaviour-based segments feeding Mautic**: evaluate Umami cohort/segment definitions (or native rules) on a schedule, resolve members to contacts through the identity table, and push as Mautic tags/segments/points (page-viewed-pricing >= 3 in 7 d, goal reached, funnel stalled at step 2). Umami cohorts cannot leave Umami and cannot reference contacts. Also write conversions back as Mautic point/stage changes and Listmonk suppression-safe lists.
4. **Server-side events API with API keys**: `POST /api/v1/events` authenticated per key, accepting `{contactId|visitor, name, data{revenue,currency,orderId}, timestamp}` and forwarding to Umami `/api/send` (or inserting natively) - handles Stripe/Shopify webhooks, offline conversions; stops exposing the body-level `ip/ts` override publicly (2.8 item 10). Add idempotency key.
5. **First-class email channel and campaign dimension**: Umami classifies email only by webmail referrer or `utm_medium` containing "mail" and mis-prefixes any medium starting with "p" as paid (Postgres) (2.4). OVELIO should (a) stamp channel at ingest from a versioned, user-editable rule table, (b) auto-tag every OVELIO link with `utm_source=ovelio&utm_medium=email&utm_campaign=<slug>&utm_content=<link-id>`, (c) expose `campaign` and `channel` as filters/breakdown/revenue dimensions (Umami: channel is not filterable, revenue has no campaign dimension).
6. **UTM builder + naming governance**, link shortener that appends UTMs and contact token (Umami `/q/` only counts and redirects, no query rewriting, `U:app/(collect)/q/[slug]/route.ts`).
7. **Better funnels**: visit-or-identity-scoped, strict step ordering (`>` not `>=`), per-step filters for path steps too, breakdown by channel/campaign, conversion window per step, drop-off timing, saved comparison against segment, "stalled contacts" export to Mautic.
8. **Retention/cohorts on identity** not session: removes the monthly-salt cliff and the 31-day cap (`getRetention.ts:97`); weekly/monthly cohorts, tz-aware.
9. **Real filter UX**: all 16 operators, OR groups, property filters, saved views, and consistent semantics (fix item 2.8-1); expose `tag` (A/B) and `distinctId`.
10. **Timezone/units/compare**: per-workspace timezone, week/month/year units, yoy compare (Umami supports; OVELIO forces UTC/day/prev).
11. **Consent-mode and privacy controls Umami lacks in UI**: DNT, GPC, per-region consent defaults, IP exclusion list in UI, domain allow-list enforced server-side (Umami doesn't enforce), bot rules, retention TTL, per-visitor erasure.
12. **Fixed-window visit and bot quirks**: implement sliding 30-min inactivity visits (Umami's is a fixed window from visit start, 2.2.6) and a configurable bot/UA/IP/ASN filter with an audit counter of dropped hits (Umami silently returns `{beep:'boop'}`, `route.ts:97-99`).
13. **Operational dashboards**: tracker health ("last hit received", script installed check), ingestion lag, dropped-hit counters - none exist in Umami or OVELIO.

## 4. Native-rebuild notes (if OVELIO owns analytics)

Licensing: Umami is MIT (`.refs/umami/LICENSE`) so schema and SQL can be adapted with attribution; Mautic/Listmonk licensing is outside this slice.

**Ingest**
- Public edge: `POST /api/collect` (+ batch) with per-site key, hostname allow-list, CORS only for the site's domains, body cap, rate limit per IP/site, UA/bot + datacenter-ASN filter, optional IP-hash. Reject caller-supplied `ip/ts` unless an authenticated server key is used.
- Parse and normalise at ingest, not at read: `path`, `query`, `referrer_domain` (strip www, eTLD+1), UTM, click ids, **`channel` (versioned rules) and `campaign_id`**, device/browser/os/geo, `event_type`, `hostname`.
- Identity: `visitor_id` (random id in first-party cookie when consented; cookieless fallback = salted hash of IP+UA+site+rotating salt like Umami's), `session_id` (server-side sliding 30-min inactivity, keyed by visitor_id), `contact_id` (nullable, from identity graph), consent flag per hit.
- Queue (Redis stream/PG-queue) between edge and writer; batch insert; idempotency key on events/revenue.

**Storage**
- Postgres is enough to roughly 10-50 M events/month if: `events` range-partitioned by month, `BRIN(created_at)` + `(site_id, created_at)` + `(site_id, session_id, created_at)` btree, JSONB `props` plus a typed `event_props(site_id, event_id, key, str, num, ts)` side table only for keys users actually filter on, hourly/daily rollup tables (visits, pageviews, per channel/campaign/path) maintained by the worker. Umami's own Postgres path shows the cost: one wide `website_event` table, 14 indexes (`U-prisma:169-182`), session join for every session-column filter.
- Move to ClickHouse when events > ~100 M/month or funnel/journey latency matters: Umami's DDL (`U-ch:1-258`) is a usable starting point (MergeTree by month, `ORDER BY (hour, site, session, visit, ts)`, hourly AggregatingMergeTree MV with argMin/argMax entry/exit states). Keep the identity graph and definitions (goals, funnels, segments, reports) in Postgres.

**Query layer**
- A filter AST compiled to SQL for both engines (the hard part Umami solves twice: `U:lib/prisma.ts` and `U:lib/clickhouse.ts`): 16 operators, AND/OR groups, session vs event columns, property filters via exists-subquery, cohort join, exclude-bounce join. Parameterise everything; whitelist columns.
- Metrics definitions to copy exactly (so numbers match Umami during migration): visitors=distinct session id, visit=distinct visit id, bounce=single-pageview-no-event visit, totaltime=sum(max-min) of pageviews (`getWebsiteStats.ts:43-74`); then decide deliberately where to improve (visitor = visitor_id not session).
- Funnels: use ClickHouse `windowFunnel` or a Postgres recursive/LATERAL "next matching event within window" with strict ordering; per-step filters; scope = visitor/identity. Journeys: window functions over visit; cap fan-out; materialise top paths nightly. Retention: first-seen cohort on identity key, tz-aware calendar buckets, no 31-day cap. Attribution: touchpoint table (visitor/contact, ts, channel, campaign, click ids) + conversion table, lookback window, models (first, last, linear, time-decay, position), revenue weighting; precompute on conversion.
- Unique counts: exact `count(distinct)` is fine in PG at this scale; HLL/`uniq` in ClickHouse.
- Timezone-correct bucketing (`date_trunc` with tz) and `compare` windows (prev/yoy) as first-class.

**Hardest parts (ranked)**
1. Identity graph + consent + erasure semantics (merge/split, many-to-many, retroactive stitching of anonymous history, DSAR delete) and keeping reports stable when identities merge.
2. Cross-engine/cross-dialect query correctness and performance for funnels/journeys/attribution on a growing table (Umami itself has Postgres/ClickHouse divergences, e.g. the channel prefix rule).
3. Bot/spam resistance on an unauthenticated public ingest endpoint (website id is public).
4. Session/visit semantics in a cookieless/consent-optional world (salt rotation vs retention).
5. Revenue integrity: currency, FX, refunds, idempotency, late/offline events.
6. Backfill/migration from Umami (keep ids, map `session_link`, replay `event_data`).
